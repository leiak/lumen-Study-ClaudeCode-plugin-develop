本参考面向任何 agent 会消费的文档:一个 skill、一份 `AGENTS.md` / `CLAUDE.md`、或一份由 pointer 指向的文档。包装方式不同,但写作方法相同:同样的几个杠杆让每一份文档都可预测,因为 agent 在每次运行中走的都是同一个**流程**,而不是产出同一个结果。

当你正在编写的文档是一份 skill 时,请阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 以了解 frontmatter、调用方式选择,以及 router skills。

## Context pointers

**Context pointer** 是 agent 上下文中持有的一条引用,它指向某份上下文之外的资料,并编码了读取该资料的条件。一个 skill 的 description 就是其一;`AGENTS.md` 中指向某份文档的一行也是同一个对象。决定 agent 何时去取该资料的,以及可靠程度如何的,是这条 pointer 的**措辞**而非其目标。一个真正需要的目标,被一句弱措辞的 pointer 挡在身后,这就是一个方差 bug:先收紧措辞,只有当收紧失败时,才把内容内联。

Pointer 有两件事要做:说明材料是什么,以及列出应当触发读取它的**分支**(分支是文档处理的一种不同情形,使得不同运行走不同的路径)。一条始终加载的 pointer,每个字都要花代价,所以它需要比正文更严格的精简:

- **前置首词**:Pointer 真正起触发作用的就靠它。
- **每个分支只用一个触发词。** 同一分支的同义词等于把同一个分支写了两遍;合并它们,只保留真正不同的分支。
- **删除正文已经承载的身份信息。**

## 两种 load

你增加的每份文档与每条 pointer 都会消耗以下两种预算之一:

- **Context load** 是常驻材料对 agent 窗口造成的成本:`AGENTS.md` 中的一行、一个 skill description、任何每轮都驻留在上下文中、无论是否触发都消耗 token 与注意力的东西。
- **Cognitive load** 是施加在人类身上的成本:存在哪些文档,何时去取哪一份。人本身就是索引。它不是要被最小化的成本:它是人类主动性的代价;在需要人类判断的地方花它,在不需要的地方去掉它。

只通过 pointer 取得的材料,以 pointer 自己那一行的代价规避了 context load;完全没有 pointer 的材料,完全靠 cognitive load 维系。

## 信息层级

一份文档由两类内容组成:**步骤**(agent 按顺序执行的操作)与**参考**(按需查阅的定义、规则、事实)。两者可以自由混合:全是步骤(一份菜谱)、全是参考(一份评审规则,也就是本 skill),或两者皆有。核心决策在于每块内容在**信息层级**上的位置——一条按"agent 多快就需要这份材料"排序的阶梯:

1. **文件内步骤** 是最高一级:agent 要做的事,按顺序。
2. **文件内参考** 是按需查阅的。常常是一组合法平等的并列条目(评审的每条规则占同一级),这是一种合理安排,并非异味。
3. **已披露的参考** 被外推到独立文件,通过 context pointer 引用,仅在 pointer 触发时才加载。从同目录下的兄弟文件,到任何位置、可被任何文档指向的完全外部参考,横跨整个范围。

下推得不够,顶层就会臃肿;下推得太多,就会把 agent 真正需要的材料藏起来。这对张力就是整个决策本身。

**Progressive disclosure(渐进披露)** 是沿阶梯向下移动的动作(从主文件移到 pointer 之后),让顶层保持可读。它主要不是为了节约 token:它是保护层级结构的方式。**Branching(分支化)** 是最干净的披露测试:每个分支都需要的东西内联,只有部分分支需要的东西挪到 pointer 之后。当文档有步骤时,本应披露的文件内参考会把步骤埋起来,把"注意到它们"变成掷硬币:这是一个方差杠杆,而不只是可读性杠杆。

**Co-location(同位)** 是文件内的对应概念:层级决定一块材料**下到多深**,同位则决定一旦到了那里,**什么放在它旁边**。把一个概念的定义、规则与注意事项放在同一个标题下,而不是散落各处,这样读到一部分就会顺便把邻近内容一起读了。检验标准:文档读起来要像为 agent 而写的文档。成组的材料读起来像;散落的材料读起来不像。(区别于**重复**:重复是把同一含义放在两个地方;散落是把一个含义碎片化到很多地方。)

**Sprawl(蔓延)** 是这里要规避的失败模式:即使每行都是鲜活且唯一的,文档依然过长。注意力在冗余中稀释,每一行多出来的内容又多了一条要保持相关的负担。治理手段就是阶梯:把参考披露到 pointer 之后,并按分支或顺序拆分,让每条路径只背负它需要的内容。

## 步骤与完成标准

每一步都以一个**完成标准**结尾——一个告诉 agent 工作已结束的条件。它成为杠杆的关键在于两个性质:

- **清晰度**:agent 能区分完成与未完成吗?一个模糊的边界("达成理解")会招来**过早完成**:在这一步真正完成之前就宣告结束,注意力滑向"已经做完"。可见的、仍在前方的步骤(即**完成后的步骤**)提供拉力;完成标准的清晰度提供阻力。按顺序防守:**先收紧边界**(局部且便宜);只有当它本质上是模糊的、**而且**你观察到抢跑行为时,才通过拆分顺序把后续步骤藏起来。隐藏只在跨过真实的上下文边界时有效(一次 handoff 或一个 subagent 派发;内联调用会让后续步骤仍留在上下文里,清不掉)。
- **要求度**:它要求多少。"每一个被改动的 model 都被登记在册"会迫使工作做得彻底,而 "产出一份变更清单" 则不会。要求度驱动**腿活儿**(agent 在工作中进行的挖掘,以措辞潜伏的方式存在,而不是被写成独立步骤),且它不受步骤约束:"每条规则都被应用"既约束一份平铺参考的整体,也约束一个序列的"每一步完成",这正是一份全参考文档依然能承担穷尽性门槛的机制。

最强的完成标准同时**可核对**且**穷尽**。

## 何时拆分

把一份文档拆成两份会消耗两种 load 之一,所以只在拆分切得赚回来时才拆:

- **按顺序拆分**:把一串步骤拆开,当前一步之后的步骤在诱惑 agent 抢跑时。将其移出视野会驱动在当前任务上做更多的腿活儿。当心反向:合并顺序会把每一步之后的下一步暴露在它面前,招来过早完成。
- **按调用拆分**:这是 skill 专属切法,见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## Leading words

**Leading word** 是一个已经在模型预训练中存在的紧凑概念,agent 在跑这份文档时会用它来思考(_lesson_、_fog of war_、_tracer bullets_)。它以 token 的形式重复出现,而不是以整句的形式,这样就能以最少的 token 累积出一个分布式的定义,并把整个行为区域锚定下来,办法就是招募模型已经持有的先验。自己造词也行,但前提是你要把它定义清楚;自造词招募不到先验:你得用定义 token 去支付本来可以由预训练词免费提供的东西;优先用现成的词。

它锚定两次。在正文里,是**执行**:每当这个词出现,agent 都会调用同样的行为;在平铺参考内部,它把注意力聚焦到一类要去识别的事物上。在一条 pointer 里,是**调用**:同一个词出现在你的 prompts、你的文档、以及你的代码库中时,agent 会把这种共享语言与材料关联起来,更可靠地触达它。

寻找用 leading word 重构的机会。在三个地方写开的三联词,一条 pointer 用一句话去指代一个想法。每一处都是一段亟待坍缩为一个 token 的文字:

- "fast, deterministic, low-overhead" → _tight_(一段 _tight_ 循环)
- "a loop you believe in" → _red_,把一个模糊的门槛变成一个二值的可观测量(循环在 bug 处变 _red_,或不变)

你赢得两次:更少的 token,以及一个更锋利的钩子,让 agent 把思考挂上去。假设每一份文档都背着一些用 leading word 就能退役的重复表述。去找它们。

**Negation(否定)** 是这一杠杆旁边的失败模式:用禁令来引导,反而把被禁止的行为拖进上下文,让它**更容易**被调用,而不是更难。_不要想大象_,于是满脑子都是大象;否定是一个弱修饰,被强烈激活的概念会压过它,因此这条禁令有一半会被读成"去做这件事"。应当**正面表达**:陈述目标行为("写单行注释"),这样被禁止的行为就根本不会被说出来。禁令只有在无法正面表达、且作为硬护栏时才有它的位置;即便如此,也要把它与正面目标搭配,让注意力落在该做什么上。

## Pruning(修剪)

- 让每条含义保留在**唯一的事实来源**:一个权威的位置,使得修改行为只需改一处。**重复**(同一含义出现在多个地方)会带来维护与 token 的双重代价,也会把一条含义在层级上的存在感抬到高于其真实等级的位置。(重复是 leading word 的意外反面——leading word 是有意识地重复一个 token,从来不重复含义。)
- **环境**也是一种事实来源(`package.json` 中的脚本、配置文件、目录布局、`--help` 输出),而一份重述环境的文档就是**缓存**:一份对查表结果的复制,只有在查表很贵时才赚回它的 load。把那些 agent 通过观察无法找到的东西缓存起来:未成文的约定、选择背后的理由、任何配置文件都不会坦白的坑。把那些"看一眼文件、敲一条命令"就能查到的留给环境,那里才不会过时。
- 逐行检查**相关性**:这一行是否还与文档要做的事有关?一行会因为从不涉及任务(纯粹的铺陈,或一个本应被披露的分支)而失去相关性,也会因为它所描述的行为或世界发生变化而过时。越短的文档越容易保持相关。没有修剪纪律,默认的命运就是**沉积**:陈旧的层次越堆越厚,因为"加"让人安心、"删"让人有风险,直到你必须向下钻穿它们,才能找到仍然鲜活的东西。
- 逐句寻找**no-op**:模型默认就会遵守的指令,说了等于没说。检验标准(它是否能改变默认行为)是相对于模型的,而不是相对于读者的:两个人对 no-op 各执一词,本质上是在争论默认行为,而不是用辩论来定夺,而应当把文档跑一遍来裁决。当一句话通不过检验时,删掉整句,而不是逐词削减。这个检验也用来给 leading word 评级:一个弱到压不过默认的词(在 agent 本来就比较 thorough 时说 _be thorough_),就是 no-op,修法是换一个更强的词(_relentless_),而不是换技术。
