---
name: grilling
description: 围绕一个计划、决策或想法对用户进行持续追问。用于当用户想要压力测试其思路，或使用任何 "grill" 触发短语时。
---

持续追问用户，直到达成共识为止。将整个沟通过程组织成一颗**设计树**:每一个决策都会派生出依赖于它的子决策。

按**轮次**推进这颗树。**前沿**是指所有前置依赖都已经确定下来的决策:这些是你现在就可以问、而不必猜测尚未听到的答案的问题。在同一轮中问完整个前沿:为每个问题编号,并给出你的推荐答案。然后等待用户的回答,再进入下一轮。

每轮的格式如下:

```
❓ **Q1** - **<问题标题>**: <问题正文,可以是多段,包含多选>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**: <问题正文,可以是多段,包含多选>

➡️ <你的推荐答案>
```

每轮用户回答后,设计树都会重塑:已确定的决策把前沿向外推,从而解锁依赖于它们的问题。重新计算前沿,开始下一轮。如果一个问题的答案依赖于本轮仍未确定的另一个问题,那么它属于**之后**的某一轮,而不是本轮。

**事实**是你的工作,绝非用户的。当一个前沿问题需要来自环境的事实(文件系统、工具等),派一个子 agent 去查找;不要向用户询问任何你自己就能查到的东西。不要因此阻塞:一个正在进行的探索本身就是一个尚未确定的前置条件,因此只有那些下游的问题需要等待子 agent 的汇报;其他前沿问题现在就可以问。**决策**属于用户:把每一个决策交给他们,等待答复。

当整个设计树的每一支都已访问过、前沿为空、所有隐含假设都不再沉默时,会话结束。在用户确认你已达成共识之前,不要采取行动。
