# MISSION.md 格式

`MISSION.md` 位于工作区根目录。它记录用户**为什么**在学习这个主题。每一个教学决策(下一步教什么、呈现哪些资源、设计哪些练习)都应回溯到这份文档。

## 模板

```md
# Mission: {Topic}

## Why
{1-3 句话。用户追求的具体真实目标。当他们掌握这项技能时,生活或工作会有什么改变?避免抽象的表述,例如 "理解 X";要追问其底层结果。}

## Success looks like
- {一项具体的、可观察到的、用户将能够做到的事情}
- {另一件具体的事情}
- {……}

## Constraints
- {时间、预算、已有的承诺、学习偏好,任何限制方法的因素}

## Out of scope
- {用户明确表示暂不涉猎的相邻主题,以保护最近发展区}
```

## 规则

- **每个工作区只允许一个任务。** 如果用户想学两个不相关的内容,那就用两个工作区。
- **具体优于抽象。** "10 月之前跑完半马" 优于 "变得更健康"。"给团队交付一个 Rust CLI" 优于 "学 Rust"。
- **对模糊之处要敢于反驳。** 如果用户说不清为什么,在写任何东西之前先追问。一份糟糕的任务比没有任务更糟。
- **现实变化时及时修订。** 任务会变。当用户的目标变化时,更新这份文件:不要让一份过时的任务继续引导后续会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏,它就不再是指南针,而是变成了一份计划。
