# Learning Record 格式

学习记录位于 `./learning-records/`,使用顺序编号:`0001-slug.md`、`0002-slug.md` 等。仅在写入第一条记录时按需创建目录。

它们是教学领域的 ADR:记录不显然的教训、关键洞察,以及将引导后续会话的既定先验知识。它们用于计算最近发展区。

## 模板

```md
# {所学或所确立内容的简短标题}

{1-3 句话:学到了什么(或确立了哪些先验知识),以及它为什么对未来会话很重要。}
```

这就是全部格式。一条学习记录可以只有一个段落。价值在于记录**已经知道了这件事**,以及**它为什么改变了接下来的教学内容**,而不是填满各个章节。

## 可选章节

仅当它们真正带来价值时才使用。大多数记录并不需要这些。

- **状态** frontmatter(`active | superseded by LR-NNNN`):当早先的理解被证伪并被取代时很有用。
- **Evidence(证据)**:用户如何展示出这种理解(回答了某道题、完成了某个练习、引用了先前的经验)。在该主张可能再被审视时很有用。
- **Implications(影响)**:对未来会话解锁或排除的内容。当不显然时,值得记录。

## 编号

扫描 `./learning-records/` 中已有的最大编号,然后加一。

## 何时写入学习记录

当以下任一情况为真时,就写一条:

1. **用户展示了对某件非平凡事物的真实理解**:不只是接触过,而是有证据表明他们能正确使用该概念。这为下一步教学划定了新的底线。
2. **用户披露了先验知识**:"我已经知道 X。" 记录它,以免后续会话重复教学。同时记录用户声明的**深度**。
3. **纠正了某个误解**:用户原本相信错误的东西,现在明白了为什么错。这些是高价值的:它们能预测相关主题未来的绊脚石。
4. **任务在学习过程中发生了转移**:用户发现自己关心的东西和之前以为的不同。交叉链接到 [[MISSION.md]] 并更新它。

### 哪些**不**算合格

- 仅仅是被讲过的材料。覆盖不是学习。等到有证据再写。
- 已经在 [[GLOSSARY.md]] 中以术语定义形式简洁记录过的内容。不要重复。
- 一次次的会话活动日志。学习记录不是日记:它们是决策级的洞察。

## Supersession(取代)

当一条更晚的记录与更早的相矛盾时(用户的理解加深或更正了),将旧记录标记为 `Status: superseded by LR-NNNN`,而不是删除它。理解如何演化的历史本身就是有价值的信号。
