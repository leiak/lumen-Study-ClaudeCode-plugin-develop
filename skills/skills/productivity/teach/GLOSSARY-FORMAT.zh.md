# GLOSSARY.md 格式

`GLOSSARY.md` 是该教学工作区的权威语言。所有讲解、练习和学习记录都应遵循其中的术语。构建术语表本身也是学习的一部分:将一个概念压缩成一个紧凑的定义,是用户真正理解它的证据。

## 结构

```md
# {Topic} Glossary

{一两句话描述本术语表涵盖的主题。}

## Terms

**Hypertrophy**:
由机械张力与代谢压力在多次训练中驱动的肌肉增长。
_Avoid_: Bulking, getting big

**Progressive overload**:
随着时间推移,通过负荷、容量或强度系统性地增加对肌肉的要求。
_Avoid_: Pushing harder, levelling up

**RPE (Rate of Perceived Exertion)**:
1-10 的自评打分,衡量一组训练感觉有多吃力,10 表示力竭,8 表示还能再做两次。
_Avoid_: Effort score, intensity rating
```

## 规则

- **仅在用户真正理解了一个术语时再加入。** 术语表是压缩知识的记录,而不是让用户去读的字典。如果用户刚接触一个概念,等到他们能正确使用它再收录进来。
- **要态度鲜明。** 当同一概念有多个词时,挑一个最好的,其余列为应避免的别名。这就是语言压缩的方式。
- **定义要紧凑。** 一两句话。定义术语**是什么**,而不是它做什么或怎么做。
- **在定义内部使用术语表中的其他术语。** 一旦某个术语进了术语表,就在各处都优先使用它,包括其他定义的内部。这会让复杂术语后续更容易理解。
- **按子标题分组**,当自然形成聚类时(例如 `## Anatomy`、`## Programming`)。当术语彼此内聚时,平铺的列表也可以。
- **显式标注歧义。** 如果某个术语在该领域内被宽泛地使用,记录所采用的取舍:"在本工作区中,'set' 始终指工作组;热身组单独记录。"
- **随理解深入而修订。** 用户在第一周写的定义,到第六周可能就是错的。就地更新;不要留着陈旧条目。
