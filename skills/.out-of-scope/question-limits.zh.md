# grilling 过程中提问数量的硬性上限

`/grill-me` skill（以及其他 skill 内部的 grilling 会话）不强制任何最大提问数。要求加上可配置上限或硬性天花板属于范围外。

## 为什么不属于范围

Grilling 故意是开放式的。要点就是一直挖到决策树的每一支都被解决：有的计划需要三个问题，有的需要五十个。一个固定的硬顶要么在难题上把有用的探索切断，要么在简单题上显得武断。

如果一场会话显得太长，已经存在的逃生口是：

- 用户可以随时停下来，承认当前计划的状态。
- 用户可以告诉模型收尾、总结、继续往下走，因为自然语言引导本就是预期的控制面，而不是一个数字上限。

加一道硬顶还会把两种不同的失败模式混在一起：模型问太多是因为计划确实欠规格（工作如设计），模型问的是冗余或低价值的问题（这是 prompt 质量问题，不是数量问题）。后者的修复该在 skill prompt 里，而不是一个计数器。
